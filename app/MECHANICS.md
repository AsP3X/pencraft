# Pencraft mechanics sheet

Every rule and number Pencraft uses.

## File format (`.pen`)

| Rule | Value | Note |
|---|---|---|
| Container | JSON, two-space indent, no trailing newline |  |
| Schema version for new files | `2.22` |  |
| Node kinds | frame, group, rectangle, ellipse, polygon, path, connector, text, note, icon, script, browser, ref (+ older `icon_font`, `line`) | `connector` is Pencraft's own |
| Connector | `from` and `to`: a layer id, `{id, side, at}` (side left, right, top, bottom, center; none = the side facing the next point; `at` 0–1 along the side, 0.5) or a free point `{x, y}` in the parent's coordinates. `via`: waypoints in order, each a point or a layer id (its middle). `route` curved (default), elbow, straight. `curvature` 1, `stub` 16 (how far an elbow runs out before turning back), `cornerRadius` rounds the turns, `dash` a length or a list, `strokeLinecap` and `strokeLinejoin` round unless set, `startMarker` / `endMarker` arrow, bar, triangle, dot, diamond, `markerSize` 8. Drawn by its stroke only; takes no room in a layout or a group; no `x`, `y`, size. An end or waypoint naming a layer that isn't there: the connector draws nothing (a missing waypoint is left out) | Pencraft's own rule. Curved handles reach half the way along the leaving direction, at least a quarter of the way across, 24 to 240; through waypoints a Catmull-Rom spline |
| Component states | a component's `states`: `{name: {root properties, descendants}}`; an instance's `state`: one name or a list, applied in order, before the instance's own overrides | Pencraft's own rule |
| Colour paint | `{type: color, color, opacity}`: the colour (or variable) at that opacity | the opacity was read but not drawn before 0.3.8 |
| Pattern paint | `{type: pattern, shape: dots / grid / lines, color, opacity, size, spacing, direction, offset}`: marks repeated across the layer, cut to its shape; `spacing` 24 (one number or `[across, down]`), `size` 2 for dots and 1 for lines, the first mark half a spacing in unless `offset` says. At most 20 000 marks a fill: a denser pattern draws every second, third, … mark | Pencraft's own rule |
| Unknown keys and kinds | kept and written back | Pencraft's own rule (round-trip) |
| Pencraft's stamp | every save writes the key `pencraft` after `version`: `{format, features}`. `format` is the number of Pencraft's own format, `1`; a higher one a file came with stays. `features` lists, by name in order, what the document uses that only Pencraft draws: `componentStates`, `connector`, `material`, `mask`, `patternPaint`, `textOnCircle`, `textOnPath` (found in layers and in what instances override); left out when there are none. Names and keys of the stamp this version doesn't know are kept. A file whose `format` is higher, or that lists a name this version doesn't know, opens with a sentence saying a newer Pencraft wrote it | Pencraft's own rule. `version` stays the schema's, which Pencraft doesn't number |
| Saved as `.pen` under a new name | when the document uses something only Pencraft draws, the save says which (once for that name, not at every save); `save_document` says it in `notes` | Pencraft's own rule |
| Bundle (`.pencraft`) | one file holding a document and the files it names: a zip archive (deflate or stored; no zip64, so 4 GB and 65 535 files at most; no encryption) with `manifest.json` (`{format: "pencraft-bundle", version: 1}`), `document.pen` (the same JSON as a `.pen` file) and each named file at the path the document names it by. Named files: the `url` of every picture and shader, the pictures a shader is given (`uniforms`), and `imports`, where they are paths inside the document's folder. `images/credits.json` goes in cut down to the pictures that go in. Files in the folder the document doesn't name stay out; a named file that isn't there is left out and the save says so. The same document and files give the same bytes | Pencraft's own format |
| Opening a bundle | unpacked into a working folder of its own under `~/.pencraft/open` (2 GB unpacked at most), where the document's relative paths start; a name that leads outside the bundle refuses the whole file. A bundle zipped again inside one folder, and the Finder's `__MACOSX` and `.DS_Store`, are read through. A higher `version` in the manifest opens with the sentence about a newer Pencraft. The folder is removed when the tab closes; folders no running Pencraft holds (a lock on `.held` inside) are removed at the next start, a minute after they were made at the earliest | Pencraft's own rule |
| Saving into a bundle | every picture file the document shows is copied into the bundle's `images/` and named from there, also one named by a full path or from outside the folder (`../`); shader files and imported documents named inside the folder come along. Going from a bundle to a `.pen` file, the named files are copied beside it, never over a file there | Pencraft's own rule |
| Which format | the file name's ending: `.pencraft` a bundle, anything else a `.pen` file. Save As offers the ending the document has (`.pen` for a new one); File › Save As Bundle… / Save As .pen File… offers the other | Pencraft's own rule |
| Crash recovery | every open document with unsaved changes is written to a folder of this run under `~/.pencraft/recovery` (`<process>-<time>/<number>.pen`, with `<number>.json` saying its file and its tab's name): when it first has changes, and again when it changed, 5 s after it was last written at the earliest; not in the middle of a drag. Saved, or closed by the user's choice, what was written of it goes; a run that ends properly removes its folder. The folder holds a locked file `.held` for as long as the run lives. At the start, the folders no running Pencraft holds are a crashed run's: a window names their documents and asks Restore or Discard. Restore opens each one's file with the kept document in the place of the file's (one step back is the file's), or as a new document when it has no file (any more); its changes count as unsaved. One that can't be brought back stays and is offered again. Not in a private run or a picture's | Pencraft's own rule. Written by a thread of its own, crash-safely. **Left out:** the undo steps, the chat's unfinished answer, and pictures added to a bundle since it was last saved |
| A file opened while Pencraft runs | `pencraft FILE…` (also the Explorer's double click on Windows, where the installer ties `.pen` and `.pencraft` to Pencraft) passes the files to the Pencraft that is already running, which opens each in a tab (or brings its tab to the front), comes to the front itself and is un-minimised; the second one ends without a window. It opens them itself when none answers. Whatever the settings say about AI models. Not with `--screenshot`, `--private`, `--background` or `--ask` | Pencraft's own rule; over the local server (`pencraft/open`, with the run's secret). **Left out:** the Finder's double click on a Mac |
| Variables | `$name`; a value list picks the last entry whose `theme` matches |  |
| Instances (`ref`) | instance properties override the component; `descendants` by id path: with `type` = replace, else merge |  |

`cargo run -p pen-doc --example pen_check -- FILES` checks that documents read, write back stably, resolve their
components and lay out with finite numbers.

## Node defaults

`enabled true, x 0, y 0, width 0, height 0, rotation 0, opacity 1, clip false, layoutMode None, justify Start,
align Start, sizing Fixed`; **frames**: `layoutMode Horizontal, width and height FitContent`; text: `fontSize 14,
fontFamily "Inter", fontWeight normal, letterSpacing 0, lineHeight 0 (font's own), textAlign left,
textAlignVertical top, textGrowth auto`; **browser** `cornerRadius 16`; **missing component** 120 × 90.
Document loading: a frame's `layout` defaults to horizontal, `gap` 0, justify/align start.

## Layout

Per axis, widths first then heights: fit content (x), fill container (x), fit content (y), fill container (y), then positions.

| Step | Rule |
|---|---|
| Fit content | A flex frame sized `fit_content` along an axis becomes the sum (main) or max (cross) of its children's footprints, plus gaps between the counted children, plus padding. Children that fill along that axis, hidden or absolute children don't count. With none counted it keeps its size (fallback, else 0). Frames without a layout never grow. |
| Fill container | Main axis: (inner size − non-fill footprints − gap × (children − 1)) ÷ fill children. Cross axis: the whole inner size. At least 1. |
| Positions | Free space = inner − footprints (not clamped). start; end: +free − gap·(n−1); center: half that; space_between: gap = free ÷ (n−1); space_around: gap = free ÷ n, start + gap ÷ 2. Cross: start / (inner − size) ÷ 2 / inner − size. |
| Footprint | a child's rotated, flipped bounding box; its corner lands on the slot |
| Local matrix | translate(x, y) · rotate · scale(flipX ? −1 : 1, flipY ? −1 : 1), around the node's origin |
| Groups | as big as their children; scaling a group in a layout scales its children (not in this version yet) |

## Text

| Rule | Value |
|---|---|
| Auto width | `ceil(maxIntrinsicWidth)` |
| Height | `ceil(paragraph height)`; fixed-width-height keeps its height |
| Line height | `round(lineHeight × fontSize)` when lineHeight ≠ 0, half leading, forced strut |
| Paragraph x | −letterSpacing ÷ 2 |
| Vertical align | only for fixed-width and fixed-width-height text |
| Resizing text | auto → fixed-width (horizontal) or fixed-width-height (vertical) |

## Drawing

| Rule | Value | Note |
|---|---|---|
| Stroke alignment default | **center** |  |
| Browser corner radius | 16 |  |
| Find layers | ⌘F, ⇧⌘F, the magnifier on the tool rail or the action "Find layers" open a small island beside the rail and clear the selection. It looks through every layer's name (as the layers list shows it), then its text, then its id, ignoring case, parents before their children; at most 200 characters. The first match is the current one; ↑ and ↓ step through and go round; a click on a line makes it current. All matches are outlined on the canvas, the current one more strongly, and it is brought into view. ↵ selects the current match (or the first) and closes; esc, the close button or a click elsewhere closes. The counter reads "2 of 7" or "7 matches"; with nothing typed "Searches names, text, and IDs"; without a match "No layers match “…”". Field row 44, lines 32, 10 lines before it scrolls, 6 above and below | **Estimated:** the island's width (300) and place, the outlines' look, and how a match is brought into view (the view moves to it, and zooms out only when it doesn't fit). **Left out:** layers inside component instances aren't searched |
| Corner radius fields | one field sets all four corners and reads "Mixed" when they differ; the button beside it ("Edit corners individually", lit while on) shows four fields under it: top left, top right, then bottom left, bottom right. Not for polygons. The file lists the corners clockwise from the top left; no value is below 0. Equal corners are written as one value, none at all for 0 (16 for a browser) | The four fields start open for a layer whose corners already differ. The corner marks in front of the fields have an **estimated** look |
| Drop shadow | offset, colour (black when unset), blur and `spread`; Gaussian sigma = blur ÷ 2. The shape is grown by the spread on every side before it is blurred (shrunk for a negative one), with round corners; a plain box's own soft shadow is the box grown by it, its corners rounder by as much. Cast by the layer's shape drawn solid (fill and stroke; the children when it has no fill), whatever the fill's opacity; when the shape doesn't hide what is under it, the shape is cut out of the shadow |  |
| Inner shadow | the fill's shape in the shadow's colour, minus that shape, shrunk by the `spread` (grown for a negative one), blurred (sigma = blur ÷ 2) and moved by the offset; drawn over the fill and under the stroke, or over the children when there is no fill |  |
| Layer blur, background blur | Gaussian sigma = radius ÷ 2; one of each per layer at most |  |
| Effect order | background blur, drop shadows, fill, inner shadows, stroke, children; a layer blur blurs all but the background blur | layer blur over the shadows is **Pencraft's own rule** |
| New effect | shadows: `#00000040`, offset 0 / 4, blur 4; blurs: radius 4; shader: no file. Listed newest first; the file writes one effect as an object, several as a list, `enabled` only when off, and leaves out an offset of 0 / 0 and a blur of 0 |  |
| Shader effect | a WebGL 1.0 fragment shader file, run last over the layer with its other effects; several run in list order, each on the one before. `pencil:object` is that picture, `pencil:background` what is behind the layer (mirrored past its edges); a picture file is read upright. `gl_FragCoord` and `@resolution` are in the node's own units, y up from its bottom edge; texture coordinates 0–1 span the node's box. A uniform's value is the layer's `uniforms` entry, else its `@default`, else 0 |  |
| How shaders are run | the file is rewritten to GLSL 450 (uniforms in one block, each sampler split into texture and sampler, `main` wrapped), checked, run once on the window's GPU over the layer's picture and read back; a shader that is missing or doesn't compile leaves the layer unshaded. A rotated layer is given the upright box around it; node units, not screen pixels, are an **assumption** | **Pencraft's own rule** (wgpu reads GLSL 450 only) |
| How effects are drawn | on the CPU: the source is painted into a bitmap at the zoom's power of two (at most 1 000 000 pixels, 2048 a side), blurred (three box blurs; exact below sigma 2), and shown as a picture, kept until what it was made from changes. A plain opaque unrotated box keeps egui's own soft shadow | **Pencraft's own rule** (egui can't blur) |
| Material | `material` on a frame, rectangle or whole ellipse: `"frosted"` (thickness `ultra_thin`, `thin`, `regular`, `thick`) or `"liquid_glass"` (variant `regular`, `clear`), with `appearance` (`auto`, `light`, `dark`), `tint`, `depth` (`control`, `bar`, `panel`; by the short side: up to 52, up to 110, larger) and `advanced` numbers. The material is the layer's background: after its shadows, before its fill; children and stroke are drawn on top. A text, icon, line, group or note can't have one. | **Pencraft's own rule** (the look follows Apple's published 2025 guidance, the numbers are tuned by eye) |
| How a material is drawn | what is painted before the layer (on the canvas colour) is drawn a blur's reach beyond it, turned into linear light and blurred (at half or a quarter of the size for wide blurs). Frosted: saturation, a little light, the tint and a 1.1-unit lit edge, on the CPU. Liquid glass: a built-in shader (`src/render/glass.frag`, through the shader effect's path) bends that picture inward along a squircle-profiled rim by Snell's law (index 1.5), shows the rim from a lightly blurred copy (a fifth of the blur), adds light from one direction and weaker from the opposite one, and dithers; without a GPU, and for any other shape, glass is drawn like frosted. `auto` is dark when what is behind is darker than 0.22 on average (linear light). Kept like other effect pictures; an idle canvas bakes nothing | **Pencraft's own rule** |
| Material numbers | each from the layer's `advanced`, else a variable named after the preset (`glass-regular-blur`, `frosted-thin-tint-opacity`), else the preset; `glass-light-angle` turns the light for the whole document (degrees clockwise from above, -45 by default). `blur` is a background blur's `radius`. The table is `Material::preset_number` in `src/material.rs` and in the skill's `references/tokens.md` | **Pencraft's own rule** |
| Glass group | a frame with `glassGroup` (a spacing, 0 to 200) draws the liquid glass of up to 8 direct children as one pane with the first one's material: their outlines are joined by a smooth minimum, so children closer than the spacing flow together. Unturned frames and children only | **Pencraft's own rule** |
| Sticky note | colour `#FEE484`, 250 × 219 min, padding 24, radius 24, text 15, white text below contrast 4.6 |  |

## Tools

| Rule | Value | Note |
|---|---|---|
| Rectangle / ellipse / polygon fill | `#CCCCCC` (polygon count 3) |  |
| New frame | fill `#FFFFFF`, **clip on**, no layout, fixed size, name `Frame N` |  |
| Polygon tool | drawn like a rectangle: fill `#CCCCCC`, 3 corners |  |
| Icon tool | a click places a 24 × 24 Lucide `heart`, centred, black or white by contrast with what is under it |  |
| Pen tool (P) | a click places a corner point, a press and pull a smooth point whose two handles mirror each other; ⇧ holds the new point (or the handle) to 45° lines from the last point; a click within 8 pt of the first point closes the path. Enter ends the path and goes back to Move, Escape or another tool ends it too; fewer than two points make nothing. ⌘Z takes the last point away. The layer: `path`, stroke `#000000` 1, no fill, its box the drawn outline's, in the frame under the first point. Dots 8, handle squares 9, lines 1 pt in the selection blue | The layer is made when the path ends and each outline is its own layer. Joining outlines and snapping to other points are left out; the points of a finished path are edited as the next row says |
| Connector tool (C) | press on a layer and pull to another: a connector between them, put into the frame both share, right under the lower of the two, selected, and the tool goes back to Move. An end over no layer (or over the ground of a board that has layers) is a free point. An end dropped in the middle third of a layer picks its side itself; nearer an edge it takes that side. A pull that ends on the layer it began on makes nothing. The new connector takes the look (stroke, width, route, markers, dash, curvature, corner radius) of the first connector in the document; without one: stroke `#8B93A1`, width 2, curved | Pencraft's own rule |
| Connector handles | a connector selected alone shows no box: a round handle at each end, a square one at each waypoint that is a point, and a dot in the middle of each stretch. Dragging an end re-attaches it by the tool's rules (the layer it would hold is outlined); dragging a waypoint moves it, on whole pixels when snapping is on; pulling a middle dot adds a waypoint there; a double click on a waypoint removes it. A connector is picked on its line (8 pt), never on its box, can't be moved, resized or turned, and has a Connector section in the properties island (route, markers, marker size, curvature or corner radius, dash, run-out, Remove waypoints) in place of Position, Layout and Fill. Handles: ends 10 pt, waypoints 8 pt, middle dots 6 pt, reach 8 pt | Pencraft's own rule. **Left out:** moving a connector whose ends are both free, sliding an end along a side (`at`), handles for connectors inside an instance |
| Path points | a double click on a path, or Enter with it selected, shows its points instead of its box; Enter, Escape (first letting selected points go) or a double click beside the path ends it. A click selects a point (⇧ adds or takes away), a click on a line its two ends; ⌘A all. Dragging moves the selected points with their handles, on whole pixels when snapping is on; arrows nudge them; Delete takes them out (an outline under two points goes, the layer with its last outline). The handles of selected points and their neighbours show; pulling one turns the other while the point is smooth, ⌥ bends it alone. A double click on a point makes it smooth (handles along the line between its neighbours, a third of the way) or sharp. ⌥ and a click on a line adds a point without changing the shape. X takes the cut: a click on a point or line opens a closed outline there or splits an open one, then the pointer is back (V too). The layer's box follows the outline unless the path has a view box of its own; a stretched path is edited in its own coordinates. Reach 8 pt for points and handles, 10 pt for lines | The smooth handle length (a third) is **estimated**. **Left out:** the pen adding to a path being edited (P leaves the editing), joining outlines, dragging a box around points, bending a line by dragging it with ⌘, copy and paste of points, snapping to other points and guides, editing rectangles, ellipses and polygons as paths |
| Scale tool (K) | factor 0.01 – 100. A selected layer moves from the anchor and everything in it scales: positions, fixed sizes, font size, letter spacing, gap, padding, stroke width, corner radius, shadows' and blurs' sizes. Layers placed by a layout keep their place; fill / fit sizes and variables are left alone. A handle scales away from the opposite side; the number field scales around the middle and restarts at 1 with a new selection |  |
| Eyedropper (I) | the pointer shows, in a round swatch beside it (radius 11, 20 right and below), the colour of what is under it: the topmost solid fill there, of the last fill a layer has; locked layers count. A click gives that colour to the selected layers as their fill (their stroke with ⌥, and always for a line or a connector), in one undo step, or with nothing selected puts it on the clipboard as a hex colour; then the tool goes back to Move. A click where nothing has a solid fill does nothing and keeps the tool. A solid colour is written `#rrggbb`, another with its alpha | Pencraft's own rule. **Left out:** the colours of gradients, pictures, strokes and effects (the fill under them is taken), and colours outside the canvas |
| Tool menus | Move menu: Move (V), Scale (K), Eyedropper (I). Shape menu: Rectangle (R), Ellipse (O), Polygon, Icon, Script, Import Image or SVG…, Import Figma; the tool in use is ticked |  |
| Import image or SVG | a picture becomes a rectangle its own size (at most 80 % of the view) filled with it, the file named relative to the document's folder when inside it; an SVG becomes one path layer in its view box. Both land in the middle of the view | placement and the SVG reading are **Pencraft's own rule** |
| Shapes need a drag | a click without dragging, or a 0 size, creates nothing |  |
| After drawing | tool → Move, new layer selected; a new frame takes in the layers it covers |  |
| Pixel snapping | pointer positions rounded while drawing (on by default) |  |
| Text tool | font size 16, empty text, black or white by contrast with the pixel under the click; a drag over 30 × 10 screen points sets its box; an empty text is deleted when editing ends |  |
| Sticky-note tool | 250 × 219 centred on the click, inside the frame under it, then editing |  |

## Selection and editing

| Rule | Value | Note |
|---|---|---|
| Polygon shape | corners on the ellipse that fills the box, the first at the top; `cornerRadius` rounds every corner, at most half the shortest side |  |
| Hitting a shape | an ellipse or polygon is hit on its shape, not on the empty parts of its box |  |
| Selection look | the box, and for an ellipse or polygon the shape's outline too; a square handle at each corner (edges resize without a handle); the size label under the box | handle and label sizes **estimated** |
| Board names | a top-level frame's name stands 4 pt above its top left corner at 11 pt, whatever the zoom. It gets only the board's width on screen and is cut with "…" beyond it. No name is shown over a board under 40 pt wide on screen, where the name would lie on another board, or under the size label or a whole name. The board under the pointer shows the whole name, over the others. A selected board's name is a pill in the selection colour (a component's in the component colour) with white letters, over the middle of the board: the counterpart of the size label under it, with its padding and corners. A whole name the turning handle would cross stands above the handle, which is every selected board's when it alone is selected; it stays there while the board is dragged. The name moves to its new place and turns into the pill, and back, over 0.22 s; at once with "Animations & effects" off. A name is part of its board to the pointer: a click on it selects the board (⇧ adds or removes it), a drag from it moves the board, and the pointer on it shows the whole name and the board's outline; it comes before whatever of the design lies under it | Pencraft's own rule; the 40 pt and the 0.22 s **estimated** |
| Polygon selection box | the box, its handles and its size label fit the polygon's corners, not the layer's own box (a triangle leaves a quarter of that empty under its base); resizing pulls that fitted box and the layer's box follows in proportion. | Pencraft's own rule |
| Turning | a press just outside a corner of the selection box (within 22 points) turns the layer around the middle of its box, several layers around the middle of the selection; ⇧ turns in steps of 15°; the label shows the angle while turning. "Rotate 90° right / left" are in the action search. A layer placed by a layout gets only the rotation | The reach and the arrow by the pointer are **Pencraft's own rule** |
| Rotation handle | a round dot on a short stem, 26 points off the middle of the selection box's top side (turned with the layer; above the selection's bounds for several layers); dragging it turns the selection like the corner zones do. | Pencraft's own rule |
| What a press grabs | decided by where the button went down, not where the pointer is once the drag is recognised | Pencraft's own rule |
| Handles on turned layers | handles sit on the turned box's corners and resize along the layer's own sides, the opposite side staying in place; mirrored layers have none | Pencraft's own rule |
| Several layers selected | one box is drawn around them all with its size under it, and none is outlined by itself; the rotation handle stands on that box | Pencraft's own rule |
| Corner-radius handles | a selected upright rectangle or frame at least 56 points on its shorter side shows a round handle inside each corner, 12 points in or at the radius; pulling one sets all four corners, up to half the shorter side | the numbers are **estimated** |
| Click picking | ⌘ = deepest. A top-level frame passes to the child under the pointer; its background picks it only with a layout or no children; while it is selected itself, a press on any of its layers takes the board, so a drag there moves all of it. Nested frames, groups and instances are picked whole, also while selected: a press on a selected one takes all of it and a drag moves all of it. Only a double click steps inside, to the layer under the pointer one level down. Once a layer inside is selected, a click on another layer in the same container picks that one, until something outside is clicked | stepping in by double click only is the user's wish (before 0.3.21 a click on a selected container went inside) |
| Duplicate | copy in place right above the original; a single top-level frame goes to free space on its right, 40 past any neighbour |  |
| Frame selection (⌥⌘G) | `Frame N`, no fill, no clip, no layout, fixed size of the bounds; group at the bounds' top-left |  |
| Add flex layout (⇧A) | direction from overlap, else wider centre spread; gap = median gap (10 for one); padding from frame edges (wrapping: 0, or 10 for one); align by least distance; ≥ 2 full-cross children stretch (cross fixed); a lone text centred |  |
| Nudge / big nudge | 1 / 10 |  |
| Locked layers | a layer with `locked: true`, and everything in it, stays where it is: a click, a double click or a drawn box on the canvas doesn't pick it (the click goes to what is behind it, also with ⌘), and when it is selected (from the layers list, or a board by its name) it shows no handles, isn't moved, resized, turned or given a corner radius by the pointer, and the arrow keys, aligning and distributing leave it alone. Its properties can still be changed, and it can be deleted. "Lock or unlock selection" (⇧⌘L, action search) locks the selected layers, or unlocks them when all are locked; the layers list shows a closed lock on a locked layer and a faint open one on the others, and a click turns it. An unlocked layer has no `locked` key | Pencraft's own rule. **Left out:** a mark on the canvas for a locked layer |
| Snap to objects | a layer moved or resized within 5 screen points of an edge or the middle of a layer beside it lands on it, on each axis by itself; the nearest wins. A moved selection takes part with the left, middle and right (top, middle, bottom) of the box around it, a resize with the sides the handle pulls; an edge lands on edges, a middle on middles. What it lines up with: the layers in the same parent that aren't selected and are in view (connectors apart), and that parent's own edges and middle. A line in rose (`#F43F5E`, 1 pt) runs through each edge or middle that lies on another's, 6 pt past what it joins, while the drag lasts. Not while ⇧ keeps a resize's proportions, for a turned or mirrored layer's resize, for a layer placed by a layout, or with Settings → Canvas → "Snap to objects" off (on by default) | Pencraft's own rule; the 5 pt and the colour **estimated**. **Left out:** snapping while drawing a new shape, a key that holds snapping off, lining up with layers in other frames |
| Equal gaps | with "Snap to objects" on, a moved selection also lands, within the same 5 screen points, where its gaps to the layers beside it are equal: half way between the nearest layer before it and the nearest after it, or as far past the nearest one as that one is from the one behind it. Layers beside it are those of the snap targets that share some of its height (for gaps across the page) or of its width (for gaps down it); the frame around it is none. An edge or middle as near wins. Each equal gap shows a line across it in the guide colour with a bar at each end (4 pt to either side), half way up what the two layers share. Not for a resize | Pencraft's own rule. **Left out:** the gap's size written beside it, rows of more than two neighbours on one side |
| Distribute | "Distribute horizontally" and "Distribute vertically" (action search; two buttons under the alignment buttons while three or more layers are selected) spread the selected layers that no layout places so the gaps between them are equal: sorted by their left (top) side, the first stays, the one reaching furthest stays at its end, the others go between; with less room than they take they overlap by the same amount. Fewer than three: nothing. One undo step | Pencraft's own rule. No shortcut |

## Canvas

| Value | Number | Note |
|---|---|---|
| Zoom range | 0.02 – 256 |  |
| Zoom in / out (⌘+ / ⌘−) | next power of two: `2^(⌊log₂z⌋+1)`, `2^(⌈log₂z⌉−1)` |  |
| Zoom to fit / selection | 40 pt margin, no zoom cap |  |
| Redrawing on zoom and pan | the design is tessellated, and its effects (blurs, shadows, materials) baked into pictures, for the power of two nearest the zoom. A zoom on the move draws what is there, scaled; the rebuild for a new power of two waits until the zoom has rested 120 ms. Only effects within half a screen of what is visible are baked; zooming out or panning past that part rebuilds at once, and while the view rests (300 ms a step) the baked part doubles outward until it is the whole design or the pictures held reach 32 million pixels. Pictures a build didn't use are kept, newest first, up to 16 million pixels, so the zoom step and place just left cost nothing to return to. A blur 8 pixels wide or more is worked out on a picture shrunk 2, 4 or 8 times (at most a quarter of its width) and stretched back; the colour curves are read from tables of 4096 steps. A mesh or a shadow smaller than one pixel of the screen on its longer side is not drawn (text under one point high never was). A rebuild for a design that is on screen already (another zoom step, another part of the canvas) is made beside the window, on a thread of its own, from copies of the scene's top-level nodes, each copied again only when it changed, and the document's variables; the window draws the list it has and swaps the new one in. Such a build doesn't wait for its pictures: each is painted and blurred by one of a few threads that last as long as the app (as many as the machine has processors, less one, at most 6; up to 32 pictures wait for each), the design is gone through again, also beside the window, only when every picture asked for has arrived or the threads are about to run out of work, and shader effects alone are still made in the window's thread. At the same zoom step the window shows the list of each such walk, with the pictures that have arrived; for another zoom step the list on screen stays, scaled, until the new one is whole. An edit and a file just opened are built in the window's thread in one go (a build beside the window is called off first), as are exports. An edit builds only what it changed: the scene's top-level nodes whose document nodes differ are built and laid out again (all of them when variables, themes, the chosen theme or the fonts changed, when top-level nodes came, went or changed places, or when a changed node holds a component or anything an instance shows; with connectors in the design every one is routed again and its top-level node counts as changed), and the list takes over the items of every other top-level node as they are, except one that draws what is behind it (glass, a background blur) where a node under it changed. Text on a moving zoom is laid out at the power of two nearest the zoom and its triangles scaled; at rest, letters up to 64 screen pixels high are laid out at their very size and larger ones at the next of four sizes to each doubling (scaled down by a sixth at most), never higher than 384 pixels (scaled up beyond). ## Chat with an assistant

| Mechanic | Value | Note |
|---|---|---|
| Who answers | the assistant picked in the message box's menu: "Claude Code · model" when the `claude` program is installed, "Anthropic API · model" when `ANTHROPIC_API_KEY` is set (`ANTHROPIC_BASE_URL` moves it), and every custom provider with the "Anthropic Messages" API and a key; the first there is by default | the API route is Pencraft's own rule |
| Models offered | Opus 5.5 (first), Fable 5.2, Sonnet 5.5, Haiku 5.5; a custom provider's own list | Anthropic's current models |
| Claude Code route | one `claude -p` run per message with streamed JSON output, none of its own tools (`--tools ""`), only Pencraft's tool server (`--strict-mcp-config`, allowed without asking), the model picked, the brief and the design guide appended to its system prompt; later messages `--resume` the session; runs in a folder of its own in the temporary folder | Pencraft's own rule; flags of Claude Code 2.1 |
| API route | `POST <base>/v1/messages`, API version `2026-10-21`, streamed, 64,000 output tokens at most, the brief, the design guide and the document guide as system prompt, the nine tools; tool calls are run and all their results sent back in one message; at most 80 requests a message; "too many requests" and server errors are retried twice | Anthropic Messages API |
| Only to Anthropic's own API | caching of the request's unchanging start, effort `medium`, tool inputs streamed as written, and for Opus 5.5, Fable 5.2 and Sonnet 5.5 a hand-over to another model when a request is declined (`fallbacks: "default"`) | Anthropic API guidance; other providers get the plain request |
| What the model is told with each message | the document in front (name and file) and the selected layers (name and id) | Pencraft's own rule |
| Layers pasted into the message box | layers copied on the canvas and pasted into the text become one chip at the cursor, followed by a space: the kind's icon (12) and the name (18 characters at most) for one layer, a stack icon and "3 layers" for several with the names under the pointer; tinted ground, 1-point edge, corner 4. A chip is deleted whole. Only layers of the document in front count; others give a notice | the chip's text size is the message's, so the cursor stays true |
| What the assistant reads for a chip | each layer's id and, in brackets and quotes, its name: `card2 ("Card")`, several joined by commas; the panel shows the name |  |
| Attaching files | + in the message box asks for files; files dropped on the window are attached too (a dropped `.pen` is opened instead). Pictures (PNG, JPG, GIF, WebP, up to 3.7 MB) and text files (any file that reads as text, up to 256 KB), 10 to a message; anything else is turned away with a sentence. The files show as one chip with a paperclip and their number; a click lists them, a click on a name takes it off. Files alone can be sent. A text file travels inside the message in a block with its name, a picture as a picture: an image block for the API, and for Claude Code one JSON line on its input (`--input-format stream-json`). The panel shows "Attached: …" under the message | The limits, the chip and how the files travel are **Pencraft's own rules** (the picture limit keeps a picture under the API's 5 MB as base64). **Left out:** typing @ to pick a file, pictures shown in the chat panel |
| A reviewer for finished designs | when the assistant's answer is done and it wrote 30 layers or more since the last review (a new headline or one more row is no design to review), a picture of the top-level layers it changed, then its four largest parts of eight layers or more enlarged twice, (with what the app counted in them) and the user's request go to a reviewer: the same engine and model in a conversation of its own, with no tools, briefed as a strict art director. It scores design quality and originality (both weighing double), craft and function from 1 to 10 and answers PASS (craft 8 or more, the others 7 or more) or REVISE with four changes at most; these go back to the assistant as a message, it works them in and answers again. Two rounds at most; when the second still asked for changes, a third look only proofreads the execution (up to ten slips: touching or cut-off text, figures off their column, unequal heights, faint text, numbers that contradict each other) and leaves the idea alone; an answer that is neither word, or a reviewer that can't be reached, leaves the design as it is. The chat shows "A reviewer looked at the design". Settings → Agents → "Have designs reviewed" turns it off (on by default) | Pencraft's own rule, after Anthropic's "Harness design for long-running application development" (a separate, strict evaluator, since a model grades its own work too kindly) and ReLook, arXiv 2510.11498 (most of the gain within two rounds) |
| Chat history | what the user and the assistant said in a design's chat is kept in `~/.pencraft/chats`, in a file named by a number worked out from the design's path (FNV-1a, 64 bits), written when an answer is done or the chat is started over (which removes it); the newest 200 lines. Opening the design brings them back into its chat, and the assistant is told the last 24 again like any engine that wasn't there. A design without a file keeps its chat from its first save on. Not in a private run | Pencraft's own rule; the design's file is not touched. **Left out:** the notes on tools used, problems, the layers a message pointed at, questions the assistant asked, and a moved or renamed design's chat |
| Replies | plain sentences without Markdown; the brief says so at its start and again as its last words, after the design guide | Pencraft's own rule: said once at the start, the rule was forgotten after long work |
| Changing assistant mid-chat | the one taking over is told the last 24 messages | Pencraft's own rule |
| Keys | a custom provider's key is read from the keychain only when a message is sent to it; never logged or shown | Pencraft's own rule |
| Panel | the user's messages at the right on a tinted bubble (86 % of the width at most), the assistant's words as plain text, one muted line per tool used (the same one in a row said once), problems in red, a spinner while it works; the newest line stays in view | Pencraft's own rule |
| Waiting for the assistant | a message of the user's stands in a bubble at the right, its lines starting at the bubble's left edge. While the model neither writes nor has a tool at work, three dots stand beside what the wait is for: "Waiting for <model>…" until anything has come back, "Thinking…" while the model thinks, and after a tool "Looking at the picture…" (a screenshot), "Reading the review…", "Finding another way…" (the tool failed) or "Planning the next step…"; from 3 s on, how long the wait has lasted ("12 s", "1 min 5 s"). Where the engine lets the model's thinking be read (the Messages API, Claude Code, Ollama, `reasoning_content` or `reasoning` of a Chat Completions provider), the sentence it thinks now stands under it in quiet letters, two lines at most; a new sentence takes over once it has 12 letters. The line over the message bar of a folded sidebar says the same words without the time and the thought | Pencraft's own rule. **Left out:** reading the whole thought, and keeping it after the run |
| A problem in the chat | a problem stands in red, and under it in quiet letters what is known of the run it comes from: the assistant (the model and what it answers through: the kind of API and the provider's host, or the program), what the assistant was doing (the tool at work with what it was about, or what it was waiting on), how far into the answer (time and tool calls), and when (UTC). A provider's refusal names its status and, where the provider gives one (`request-id` or `x-request-id`), the request's ID; an error in the middle of a streamed answer says that it came from the provider while the model was answering, with the provider's kind or code. "Copy details" under it puts the problem's words, these facts and the app's version and system on the clipboard as lines of text, and says "Copied" for 1.6 s. Never in it: the key, the address beyond its host, anything of the conversation | Pencraft's own rule |
| Sending | Return sends, ⇧Return starts a new line; sending opens the chat panel; while the assistant works the send button is a stop button | Pencraft's own rule |
| From the command line | `--ask MESSAGE` sends a message at start, `--assistant ID` picks who answers, `--private` leaves the settings and remembered tabs alone; `RUST_LOG=info` writes the chat's lines to the terminal | Pencraft's own rule |
