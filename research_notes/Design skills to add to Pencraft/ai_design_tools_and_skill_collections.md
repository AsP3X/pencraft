## 1. What do AI design tools bundle?

### Takeaway
Every comparable product ships the same three layers: (a) a design-system layer (tokens, themes, component kits, importable from code or a URL), (b) task-type guidelines (landing page, mobile app, web app, slides, tables) and (c) a style layer (named aesthetic presets or tag-selected style guides). Since early 2026 the common carrier for layer (a) is a DESIGN.md file, and products increasingly accept arbitrary user SKILL.md files on top of their built-ins.

**Impeccable (impeccable.style, pbakaus/impeccable)**
- Started from Anthropic's frontend-design skill; Apache 2.0; 24 commands; 62 deterministic "slop" detector rules that need no LLM; supports 19 agent tools; GitHub badge shows 113k stars. — [Impeccable README](https://raw.githubusercontent.com/pbakaus/impeccable/main/README.md), [impeccable.style](https://impeccable.style)
- Commands: Steer: `bolder`, `quieter`, `distill`, `colorize`, `typeset`, `layout`, `animate`, `delight`, `overdrive`. Review: `critique` (scored UX review), `audit` (technical quality report, findings ranked P0-P3). Finish: `polish`, `harden` (errors, i18n, overflow, edge cases), `clarify` (rewrite unclear copy), `adapt` (screen sizes), `optimize`, `onboard` (first-run flows and empty states). Iterate: `live`, `generate` (variants of a named element). Plan/setup: `shape` (plan UX before code), `init` (writes PRODUCT.md), `document` (writes DESIGN.md), `extract` (pull repeated patterns into the design system). — [Impeccable README](https://raw.githubusercontent.com/pbakaus/impeccable/main/README.md)
- Named tells the detector checks: Inter for everything, purple-to-blue gradients, cards nested in cards, grey text on coloured backgrounds, rounded-square icon tile above every heading, "AI beige" with italic serif display type, hero eyebrow chips, numbered section labels, status-chip soup, everything-equal layouts, generic CTAs, cramped padding, skipped heading levels. — [impeccable.style](https://impeccable.style)

### Inferences
- The stable architecture across Pencil, Stitch, Claude Design, Subframe and Figma Make is: one persistent design-system document per project (tokens + component rules + do/don't), checked against the output, plus short task-type guides loaded on demand. Pencraft has the method guide and component skill but no per-project design-system document and no task-type guides.
- Pencil's guideline topics are the closest direct benchmark for Pencraft: landing-page, mobile-app, web-app, slides, table, design-system (code and tailwind are irrelevant to a picture-only tool). Pencraft's four skills map onto none of those task types.
- Self-check is now a product feature (Claude Design auto-corrects against the system; Impeccable's 62-rule detector; pptx's render-and-inspect loop; DESIGN.md `lint` with WCAG contrast). A deterministic checker over canvas nodes is feasible for Pencraft because the canvas is structured data.
- Accepting user SKILL.md files (Pencil, Magic Patterns) is becoming table stakes, which shifts the value of built-ins towards what is hard to get elsewhere: canvas-specific guidance and curated data.

### Gaps
- Pencil's own MCP server on this machine was not running, so I could not read the current `pen-dev` skill or list its styles. The locally installed tool descriptions (not a citable web source) say `read_skill` returns a SKILL.md with referenced files such as `execute.md` and `guide/web-app.md`, and `get_style` returns "visual style archetypes" with "configurable fonts, colors, and imagery" selected by name with parameters. This suggests Pencil replaced tag-based style guides with parameterised named styles, but I could not confirm the list or count.
- The Shadcn/Halo/Lunaris/Nitro kit names come only from a search digest of a docs page that now 404s; contents and component counts of each kit are unverified.
- Canva and Adobe Express: the Canva templates page returned HTTP 403; no AI-specific bundled design knowledge (beyond Brand Kit, which I did not verify) could be confirmed. Adobe Express was not researched.
- No source found describing a "skills" feature or bundled templates inside Claude Design itself.
- Figma MCP "design system rules" (the generated rules file for coding agents) was not fetched; only Make kit guidelines were.
- v0's and Lovable's internal design system prompts were not examined.

## 2. Which public design Agent Skills are most used, and what do they hold?

### Takeaway
The most-installed design skills are almost all taste/anti-generic guidance (frontend-design, web-design-guidelines, taste-skill, Impeccable, emil-design-eng); the one big data-table skill is UI UX Pro Max, which is a searchable database keyed by product type. Motion skills are numerous but irrelevant to a static canvas.

- Impeccable, Stitch skills and Anthropic's skills: see section 1.

### Inferences
- Two skill shapes dominate: "taste prose with an anti-pattern list" (Anthropic, Impeccable, taste-skill) and "lookup tables keyed by product type" (UI UX Pro Max). Pencraft's method guide is the first shape; it has nothing of the second.
- Style-specific skills exist as separate small units (glassmorphism, minimalist-ui, industrial-brutalist-ui), the same shape as Pencraft's liquid-glass. That pattern scales to more named styles.
- Ideas that transfer directly to a static canvas: `break-ui` (worst-case content), `prototype`/`generate` (several variants side by side, natural on a canvas), `learn-taste` (persist user corrections), `critique`/`audit` (scored review), `bolder`/`quieter`/`distill` (directional refinement verbs).
- brandkit ranks in the top 20 with 390K lifetime installs, evidence that brand-identity boards are a demanded output.

### Gaps
- skills.sh's own leaderboard was not fetched; rankings come from a third-party tracker.
- awesome-agent-skills lists were not reviewed.

- The Vercel rule file (`command.md`) was not fetched, so its rule categories are unconfirmed.
- What `brandkit` and `image-to-code` actually contain was not read.

## 3. Which kinds of design do users ask AI design tools for?

### Takeaway
On UI-oriented tools the recurring categories are landing pages, dashboards, auth screens, blog/portfolio, e-commerce and reusable components/design systems; on general design platforms the demand is presentations, social media graphics, posters/flyers, logos and documents. Slides appear in both groups.

### Cited Findings
- v0 community categories: Apps & Games, Landing Pages, Dashboards, Components, Login & Sign Up, Blog & Portfolio, E-commerce, AI, Animations, Design Systems, Layouts, Website Templates, Agents. — [v0 template categories](https://v0.app/templates/categories)
- Lovable subcategories: Portfolio, SaaS, Blog, Internal Tools, Dashboards, Editorial, Developer Tools, Music, Ecommerce, Events; cached views show roughly 48 to 112 templates depending on filter. — [Lovable templates](https://lovable.dev/templates)
- Claude Design's stated outputs: prototypes, slides, one-pagers; exports to PDF and PowerPoint. — [Anthropic announcement](https://www.anthropic.com/news/claude-design-anthropic-labs), [VentureBeat](https://venturebeat.com/technology/anthropic-ships-major-claude-design-overhaul-with-design-system-imports-code-round-trips-and-a-fix-for-its-token-burning-problem)
- Pencil treats slides as a first-class surface (a "Slides and presentations" docs page and a `slides` guideline topic) alongside landing-page, mobile-app and web-app. — [Pencil docs](https://docs.pencil.dev/), [Lullabot guide](https://lullabot.github.io/prompt_library/design/skills/pencil-designer/references/mcp-tools-guide.md)

- UI UX Pro Max's 194 product types show which industries skill authors expect: SaaS, fintech, banking, clinics, e-commerce, restaurants, hotels, portfolios, agencies, habit trackers, meditation apps and so on. — [UI UX Pro Max README](https://raw.githubusercontent.com/nextlevelbuilder/ui-ux-pro-max-skill/main/README.md)

### Inferences
- For a static-picture tool the highest-demand surfaces Pencraft does not yet guide are, in rough order: landing/marketing pages, dashboards (with charts), slide decks, social media graphics, posters/one-pagers, auth and onboarding screens, e-commerce screens, portfolio/blog pages.
- Slides, social graphics and posters need fixed-format knowledge (canvas sizes, safe areas, text-size floors) that UI guidance does not cover; this is a distinct knowledge type from UI patterns.

### Gaps
- No verified category counts from Canva (HTTP 403), Figma Community, Dribbble (empty page) or Stitch's example gallery. From memory, unverified: Dribbble's shot filters are Animation, Branding, Illustration, Mobile, Print, Product Design, Typography, Web Design.
- No usage statistics from any vendor on what prompts users actually send.

### Takeaway
Measured against the products and skills above, Pencraft's biggest absences are a per-project design-system document, style/palette/font data tables, task-type guides (landing page, dashboard, mobile app, slides, social/poster), chart guidance, and a critique/audit pass.

- Pencraft already covers: general method, one named style (liquid-glass), standard controls with tokens and states, device frames, logos. It lacks everything in the list above except partial overlap with states (inside ui-components).

- Poor fit: motion skills (a large share of public design skills), code-stack guidance, performance optimisation, image-to-code.
- Social media graphics and illustration have strong demand evidence on Canva-type platforms but almost no public agent skill addressing them; this is a gap in the ecosystem rather than something to copy.

### Gaps
- No public skill found for illustration style, icon drawing, or social-media format specs; absence is from the sources reviewed, not an exhaustive search.
- Accessibility skills were identified by name only; their rule content was not read.

## 5. Evidence on which bundled knowledge improves output most

### Takeaway
Published evidence is thin and qualitative. Anthropic's write-up claims the largest gains come from typography direction, a committed named aesthetic and explicit lists of defaults to avoid, delivered as a short skill loaded on demand; no vendor has published measured evaluations.

### Cited Findings
- Anthropic, "Improving frontend design through Skills", November 12, 2025: generic output is explained as "distributional convergence", safe choices dominate training data so the model samples the high-probability centre; the model is highly steerable when told otherwise. — [Anthropic blog](https://claude.com/blog/improving-frontend-design-through-skills)
- The post's levers: typography ("Typography instantly signals quality"; avoid Inter/Roboto, use high-contrast pairings and extreme weight/size differences), themes (commit to a named aesthetic), colour ("Dominant colors with sharp accents outperform timid, evenly-distributed palettes"), motion, backgrounds (atmosphere and depth instead of solid fills). — [Anthropic blog](https://claude.com/blog/improving-frontend-design-through-skills)
- The post notes that mandating interesting fonts "seems to encourage the model to improve other aspects of the design as well", and that models re-converge on new favourites (e.g. Space Grotesk) unless told to vary. The general skill is about 400 tokens and is loaded only when needed, so it adds no permanent context cost. Evidence is side-by-side screenshots only: no metrics, sample sizes or blind ratings. — [Anthropic blog](https://claude.com/blog/improving-frontend-design-through-skills)
- The current frontend-design skill has moved beyond that post: it now lists the earlier "improved" looks (cream + serif + terracotta, near-black + acid accent, broadsheet hairlines) as tells to avoid, and adds a plan-then-review-then-build process. — [frontend-design SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md)
- Impeccable and DESIGN.md tooling rely on deterministic checks (62 detector rules; lint with WCAG contrast) rather than more prose. — [Impeccable README](https://raw.githubusercontent.com/pbakaus/impeccable/main/README.md), [design.md spec](https://raw.githubusercontent.com/google-labs-code/design.md/main/README.md)
- Claude Design's June 2026 update checks output against the imported design system and auto-corrects before showing it; Anthropic says error rates dropped but gives no figures. — [VentureBeat](https://venturebeat.com/technology/anthropic-ships-major-claude-design-overhaul-with-design-system-imports-code-round-trips-and-a-fix-for-its-token-burning-problem)
- Counter-evidence on guidelines alone: a Figma Make user reported guidelines being followed while an existing component was still not reused. — [Figma forum](https://forum.figma.com/report-a-problem-6/make-kit-feature-55860)
- Tessl publishes eval pages for registry skills including UI UX Pro Max. — [Tessl evals page](https://tessl.io/registry/skills/github/nextlevelbuilder/ui-ux-pro-max-skill/ui-ux-pro-max/evals)

### Inferences
- Anti-pattern lists age: yesterday's recommended alternative becomes today's tell. Bundled style knowledge needs variety mechanisms (many presets, random or context-keyed selection, as taste-skill's layout "deal" script does) rather than one fixed good taste.
- The direction of travel in 2026 is from prose guidance to guidance plus verification: plan tokens first, build, then check against the system or a rule set. For Pencraft that argues for a token-plan step and a post-draw check in addition to more skills.
- Short, on-demand skills selected by task type are the pattern the evidence supports; one large always-loaded guide is not.

### Gaps
- No controlled evaluation comparing kinds of bundled design knowledge was found from any vendor. The Tessl eval page was not opened, so its method and scores are unknown.
- The Anthropic post predates mid-2026 models and concerns HTML/CSS output; its transfer to canvas-tool drawing is untested.
- No evidence found on whether large lookup tables (UI UX Pro Max style) outperform short taste prose.
