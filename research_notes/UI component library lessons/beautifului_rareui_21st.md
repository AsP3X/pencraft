## 1. Beautiful UI (beautifului.dev): what it is, author, components, tokens, AI surface

### Takeaway
Beautiful UI is a small (21 items), MIT-licensed showcase of "primitives for AI-native interfaces" (agent chat, thinking, approvals, tool chips, diff tables) by Shane Levine / Turbo design studio. It has no registry, CLI, npm package, llms.txt or MCP; its value for Pencraft is its very disciplined token system (9 neutral surface/ink/line steps in OKLCH, 4 named radii, 6 named elevation shadows built as "1px ring + multi-layer soft shadow") and its dense 11-14px type scale.

### Inferences
- The library is a design-studio lead magnet: its subject is "UI for agents", but it does nothing to be consumed by agents. Its lesson for Pencraft is the token discipline, not the distribution.
- The elevation system is the most copyable recipe found in this research: every surface gets a 1px ring (line colour in light, white 10-15% in dark) plus a 5-6 layer shadow whose individual alphas never exceed 5%. In dark mode the drop shadow is cut to 1-2 layers and the ring carries the edge; ring alpha rises with elevation (.10 btn, .11 card, .13 raised, .15 overlay).
- The inner top highlight on coloured buttons is 14% white, 1px, inset (`inset 0 1px 0 rgba(255,255,255,.14)`), slightly stronger than the commonly quoted 10%.
- Near-neutral greys carry a very small blue chroma (0.001-0.01 at hue 247-286), so "grey" is never pure grey.
- Its component list is a ready-made inventory for an "AI product UI" skill: thinking trace, tool chips, approval card, prompt bar, task rows, diff table, recommendation card with confidence meter, context/source cards.

## 2. RareUI (rareui.in): what it is, author, components, recipes, AI surface

### Takeaway
RareUI is a free MIT React/Tailwind/Framer Motion library by one developer (Swapnil Kalambe, "Swappy") with about 22 documented components despite "50+"/"100+" marketing; it is effect-driven (gooey liquid button, glass shimmer, neumorphic buttons, noise-textured profile card, vapor text). Its recipes are useful as "special effect" presets, and its AI support is minimal: an "AI Prompt" button that copies `Create this component for <platform>:` plus the source.

### Inferences
- RareUI is a one-person, low-adoption project (47 stars, no pushes since April 2026); treat it as a recipe book for a few showy effects, not as an authority on system design. Its marketing counts are not reliable.
- Static-design-relevant recipes: (a) glass pill = dark translucent fill + 1px white/10 border + 1px gradient hairline on the top edge (white/40) and a fainter one on the bottom (white/10); (b) neumorphism = 4 shadow layers, two outer (light one side, dark the other) and two inset mirrored; (c) premium card = thick frame border + noise overlay + 1px grid at 20px + radial spot; (d) coloured glow under a button = shadow with large Y offset and negative spread in the button's own colour at 20% alpha.
- The gooey/liquid, shimmer sweep, vapor and magnetic effects are motion effects; in a static tool only their resting frame (the sheen band, the drops) is reproducible.
- Even this library's own source has a broken shadow value, which is a reminder that scraped recipes need validation before becoming presets.

## 4. Across all three: recurring high-quality visual patterns with exact values, for a static design tool

### Takeaway
The repeatable "premium" look reduces to a handful of static recipes: a 1px ring plus a many-layer very-low-alpha shadow for elevation; a 1px inset white highlight (10-14%) on filled buttons; white-alpha hairlines instead of grey borders in dark mode; glass as translucent fill + blur + white/10 border + gradient top hairline; noise/grid/radial overlays; and radius that steps down a few pixels at each nesting level.

### Cited Findings
- Layered elevation (light), 6-layer card: `0 0 0 1px <line>` + `0 18px 47px #00000008, 0 7.5px 19px #00000005, 0 4px 10.5px #00000005, 0 2.3px 5.8px #00000003, 0 1.2px 3.1px #00000003, 0 .5px 1.3px #00000003`. Raised: ring + `0 17.54px 23.39px #0000000a, 0 9.4px 12.5px #00000008, 0 5.25px 7px #00000005, 0 2.79px 3.72px -2px #00000003, 0 1.16px 1.5px #00000003`. Overlay: ring + `0 25px 50px #0000000d, 0 12px 24px #0000000a, 0 6px 12px #00000008, 0 3px 6px #00000005, 0 1.5px 3px #00000005`. — [Beautiful UI CSS](https://beautifului.dev/_next/static/css/916c3f25c8795666.css)
- Layered elevation (dark): ring in white alpha + short black drops: card `0 0 0 1px white/.11, 0 1px 2px black/.2, 0 2px 6px black/.2`; raised `0 0 0 1px white/.13, 0 2px 10px black/.22`; overlay `0 0 0 1px white/.15, 0 8px 28px black/.34`; button `0 0 0 1px white/.1, 0 1px 2px black/.3`. — [Beautiful UI CSS](https://beautifului.dev/_next/static/css/916c3f25c8795666.css)
- Button edge in light mode: `0 0 0 1px <line-strong>` + `0 0 4px 0 #0000000a` (ring + 4% ambient). — [Beautiful UI CSS](https://beautifului.dev/_next/static/css/916c3f25c8795666.css)
- Inner highlight on a filled button: `inset 0 1px 0 rgba(255,255,255,0.14)`, optionally with `0 1px 2px rgba(16,24,40,0.1)` drop. — [beautifului.dev](https://beautifului.dev)
- Inset field (pressed/input well): `inset 0 1px 2px black/.12` light, `black/.4` dark. — [Beautiful UI CSS](https://beautifului.dev/_next/static/css/916c3f25c8795666.css)
- Hairline ring colour that works in both themes: 5% black in light, 18% white in dark (`light-dark(#0000000d,#ffffff2e)`), 1px. — [Beautiful UI CSS](https://beautifului.dev/_next/static/css/916c3f25c8795666.css)
- Focus ring: `0 0 0 1.5px <accent>`; separation ring on overlapping avatars: `0 0 0 1.5px <background>`; unchecked control: `inset 0 0 0 1.5px <line-strong>`. — [beautifului.dev](https://beautifului.dev)

### Inferences
- Rule of thumb derivable from Beautiful UI's stacks: each layer roughly halves offset and blur of the previous one (25/50, 12/24, 6/12, 3/6, 1.5/3) while alpha steps down 5% -> 4% -> 3% -> 2% -> 2%. Pencraft can generate such stacks from two inputs (largest offset, layer count) instead of storing literals.
- "Border" should be modelled as a ring (outside stroke at alpha) that composes with the shadow, since that is how the best-finished library here draws every edge; a design tool whose strokes are opaque greys will look heavier in dark mode than these references.
- Inner highlight inside radius = outer radius minus padding holds across both libraries (8/7 with 2px... approximately; 27/26/24), so a nesting helper (inner = outer - gap, floor at 2-4px) reproduces the look.
- 21st contributed no verifiable numeric recipes because its code is gated; any values attributed to its popular components would be guesses and are therefore omitted.

### Gaps
- No exact specs were obtained for 21st's popular shader/gradient backgrounds, texture buttons or hero glows (code gated).
- None of the three sites publishes written guidance on optical padding, icon sizing or radius nesting; the numbers above are measured from markup, not stated rules.
- Noise/grain parameters (frequency, opacity) are not specified numerically; RareUI references an external noise SVG.

## 5. How these libraries tell an AI which component to pick and how to adapt it

### Takeaway
Only 21st has a real answer: free metadata search (name, description, up to 5 tags, registry type, author, score), reranking against a per-project design-context file, and published skills with explicit procedures and "design rules" that put project tokens and existing components ahead of catalogue novelty. Beautiful UI and RareUI give an agent nothing beyond one-line descriptions and (RareUI) a raw "create this component" prompt.

### Cited Findings
- Search result fields exposed to agents: `name`, `slug`, `description`, `registry` (ui/hooks/blocks/icons), `visibility`, `install_ref`, `url`, `preview_url`, `tags`, `author`, `updated_at`, `score`. Install payload adds `files`, `dependencies`, `registry_dependencies`, `index_css_url`, `preview.preview_image_url`. — [openapi.json](https://21st.dev/openapi.json)
- CLI search filters: `--type c|theme|template`, `--tag <slug>`, `--color <bucket>`, `--sort`, `--free|--paid`, `--author`, `--mine`, `--liked`, `--json`; `--context auto` reranks against the project. Icons are "searchable by meaning". — [CLI skill](https://21st.dev/.well-known/skills/21st-cli-use/SKILL.md), [build skill](https://21st.dev/.well-known/skills/21st-ui-build/SKILL.md), [llms.txt](https://21st.dev/llms.txt)
- Eight published skills at `/.well-known/skills/index.json`: 21st-cli-use, 21st-ai, 21st-registry, 21st-design-sync, 21st-ui-build, 21st-ui-explore, 21st-ui-review, 21st-video; installable with `21st install-skill`. Each has a description written as a trigger spec ("Use when ... Trigger for requests such as ... Use X first when ... Do not use for ..."). — [skills index](https://21st.dev/.well-known/skills/index.json), [explore skill](https://21st.dev/.well-known/skills/21st-ui-explore/SKILL.md)
- Build workflow (21st-ui-build): read `.21st/design.json` and `.21st/DESIGN.md` (create with `21st init --design-context`); inspect target route, closest components, tokens - "Treat explicit project facts as stronger than generic taste"; "Search before generating"; "Reuse installed project primitives first. Retrieve or install a 21st result only when it reduces duplication or materially improves the result"; generate 3 variants only if nothing fits and AI is enabled; implement in the project's real framework; preserve responsive, keyboard, focus, reduced motion, "loading states, empty states, and error states"; run `21st review`. — [build skill](https://21st.dev/.well-known/skills/21st-ui-build/SKILL.md)
- Design rules given to the agent: "Prefer project tokens over new arbitrary values. Prefer existing components over parallel lookalikes. Preserve established density, radii, typography, iconography, and layout rhythm unless the user explicitly requests a redesign. Use real product copy and states when available. Avoid decorative gradients, excessive cards, glass effects, huge headlines, and animation unless supported by the project or requested. Never claim a component, token, or capability exists without inspecting it." Handoff: "Record a durable visual choice in `.21st/design.json` under `decisions`". — [build skill](https://21st.dev/.well-known/skills/21st-ui-build/SKILL.md)
- Explore rules: "Define three named directions. Each direction must differ on at least two meaningful axes such as hierarchy, information density, navigation model, content emphasis, interaction pattern, or composition. Color-only variants do not count." Shared constraints stay fixed. Per-direction contract: name, core idea and intended user effect, references used, what stays consistent, two or more differences, accessibility/responsive risks, best-fit scenario. "Do not generate random style mutations." — [explore skill](https://21st.dev/.well-known/skills/21st-ui-explore/SKILL.md)
- Review rules: separate "deterministic defects" from "subjective design recommendations"; priorities include "hardcoded visual values that conflict with project tokens; duplicate primitives instead of existing components; inconsistent typography, radius, spacing, shadows, and icons; fake data, placeholder copy, or missing empty/error states"; "Never silently redesign"; "If no issue is proven, say so and state what was inspected." — [review skill](https://21st.dev/.well-known/skills/21st-ui-review/SKILL.md)
- Adaptation instructions in the copy prompt: ask about props/data, state, assets, responsive behaviour and placement before integrating; "Modify the component as needed to fit the existing codebase + design" (Magic Patterns variant) vs "Do not change the component's code unless it's required to integrate or the user asks you to" (default variant); user-saved "prompt rules" inject tech stack, theme CSS, custom colours and spacing into every copied prompt. — [prompts.tsx](https://github.com/serafimcloud/21st/blob/main/apps/web/lib/prompts.tsx)
- Agent discoverability mechanics: `.md` twin of pages and `Accept: text/markdown` negotiation with an `x-markdown-tokens` hint; RFC 9727 API catalog; `/.well-known/ard.json`; `auth.md` with OAuth 2.1 dynamic client registration; llms.txt has a "Names & aliases (important for accuracy)" section and a "Preferred summary style for AI". — [llms.txt](https://21st.dev/llms.txt)
- Component-level description style on 21st: one sentence naming structure, states and variants (Agent Chat: "composing a scrollable message list with an input composer at the bottom. Supports user/assistant text bubbles, error states, attachment chips, and a centered empty state"); variants are separate demo slugs (`agent-chat/error`, `agent-chat/empty-centered`, `button-1/secondary`, `native-button/glow`). — [agent-chat.md](https://21st.dev/@serafimcloud/components/agent-chat.md), [ai-chat.md](https://21st.dev/community/components/s/ai-chat.md), [button.md](https://21st.dev/community/components/s/button.md)
- Beautiful UI: selection information is only the numbered name plus a one-line functional description per component. ### Inferences
- Lessons that transfer to Pencraft skills and its component library:
  - Give every reusable component a one-sentence description that names anatomy, supported states and variants, plus at most 5 tags and a type (primitive / block / icon / background). That is the whole metadata 21st relies on for selection.
  - Model variants and states as named demos of one component (default, error, empty, disabled, secondary, glow), each with light and dark previews, so the assistant picks a state by name instead of inventing it.
  - Keep a per-document design-context record (tokens, density, radii, type, prior decisions) and make "use the document's variables and existing components before any new value" a hard rule; record each accepted direction as a decision. This is 21st's main defence against off-brief output.
  - Write skill descriptions as trigger specs with explicit "use when / do not use for / use X first when" boundaries, as 21st's do.
  - When the user asks for options, require directions that differ on two structural axes, never colour-only.
  - Make showy effects opt-in: glass, gradients, glow and oversized headlines only when requested or already present in the file.
  - Add a review pass with deterministic checks (off-token values, duplicated lookalike components, inconsistent radius/spacing/shadow/icon size, placeholder copy, missing empty/error states) and report subjective points separately.
  - A prompt that hands over a recipe should carry: the spec itself, a usage example, its dependencies (other components/tokens it needs), the theme additions it requires, questions to resolve before placing it, and a closing guard against abbreviating or silently altering it.
- Free search metadata with gated code is a workable split for an AI: selection needs descriptions and tags, not source. Pencraft's assistant could select from a compact index and load a full recipe only for the chosen item.

### Gaps
- The schema of `.21st/design.json` and how `get_inspiration` reranks against it are not documented in the pages read.
- The `21st-ai` and `21st-registry` skill files were listed but not read in full.
- Whether 21st scores or curates components for quality beyond "catalog review" and `submit_for_featuring` is not documented in the sources read.
- No evidence was found on how well these mechanisms work in practice (no independent benchmark of selection accuracy).
