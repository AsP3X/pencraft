# Magic UI and Aceternity UI: static visual recipes, composition patterns, and critique (as of 2026-11-14)

Method note for the report writer: recipe values below were extracted from each library's shadcn registry JSON (the shipped component source) through a fetch-and-extract tool, not by reading raw files directly. Class strings are quoted as returned; a handful of long strings were returned in segments. Treat numbers as high-confidence but not byte-verified. Items marked UNVERIFIED come from memory or inference, not from a fetched source. Tailwind scale reminders used in the recipes: 1 unit = 4px (h-56 = 224px, w-[30rem] = 480px); blur-sm 4px, blur-md 12px, blur-xl 24px, blur-2xl 40px, blur-3xl 64px; rounded-md 6, lg 8, xl 12, 2xl 16, 3xl 24px; neutral-950 #0a0a0a, neutral-900 #171717, neutral-800 #262626, neutral-700 #404040, neutral-500 #737373, neutral-400 #a3a3a3, neutral-300 #d4d4d4, neutral-200 #e5e5e5, neutral-50 #fafafa; slate-950 #020617; cyan-500 #06b6d4, cyan-400 #22d3ee; indigo-500 #6366f1; sky-500 #0ea5e9 (Tailwind default palette, not re-fetched).

### Inferences
- Both libraries have converged on the same commercial shape: free "effect" primitives as marketing, paid full sections/templates at about $199 lifetime.
- For a static design tool, the high-value free items are the ones with a strong frozen frame (patterns, spotlights, lamp, beams, device mockups, bento, marquee rows, dock, terminal, tweet card). Text effects such as Typing Animation, Hyper Text, Morphing Text, Flip Words have no distinctive static look beyond plain text plus a cursor block.

### Gaps
- Magic UI's site groups components into categories in its sidebar, but llms.txt is flat; the grouping above is mine.
- Exact names of all 183-200 Aceternity Pro blocks were not enumerated (catalog at https://ui.aceternity.com/api/components was not fetched).
- PkgPulse claims Magic UI has "150+" components and Aceternity "~50"; both contradict the libraries' own indexes (about 80 and 100+) — [PkgPulse](https://www.pkgpulse.com/guides/react-bits-vs-aceternity-magic-ui-2026) vs [Magic UI llms.txt](https://magicui.design/llms.txt) and [Aceternity pricing](https://ui.aceternity.com/pricing). Trust the primary sources.

## 2. Exact static recipes from source

### Takeaway
Almost every effect reduces to a small set of static ingredients a design tool can draw: a 1px hairline pattern (grid 40px, dots 16-20px) faded by a radial or linear mask; a blurred coloured ellipse or conic wedge; a 1px border ring filled with a gradient via mask-composite; a short gradient streak that fades to transparent; and a card with white/10 border plus an inset top glow. Default accent pairs are orange-to-violet (#ffaa40 to #9c40ff) in Magic UI and cyan-to-indigo-to-violet (#18CCFC, #6344F5, #AE48FF) in Aceternity.

### Cited Findings — Magic UI

- Grid Pattern: SVG pattern cell 40x40, path `M.5 40V.5H40` (top and left hairlines only), offset -1,-1, fill and stroke gray-400/30, optional dash array, optional highlighted squares of (cell-1)px filled with the same 30% grey — [grid-pattern.json](https://magicui.design/r/grid-pattern.json).

- Particles: 100 round dots, colour #ffffff, radius 0.4 or 1.4px, alpha 0.1-0.7, fading within 20px of edges — [particles.json](https://magicui.design/r/particles.json).
- Light Rays: 7 rays, colour rgba(160,210,255,0.2), each 160-320px wide, 70vh long, starting at top -12%, x 8-92%, rotated -28 to +28deg from a top origin, fully rounded, vertical gradient from 70% colour to transparent, blur 36px, screen blend, peak opacity 0.6-1.1; plus two ambient radial glows at 60% opacity: circle at 20% 15% (45% colour to transparent at 70%) and circle at 80% 10% (35% colour to transparent at 75%) — [light-rays.json](https://magicui.design/r/light-rays.json).
- Warp Background: content padded `p-20` (80px) inside a bordered `rounded` box; four walls (top/bottom/left/right) in 100px perspective, each a grid of 1px lines in the border colour on a 5%-of-container cell; 3 beams per wall, each a cell wide with aspect 1:1 to 1:10, gradient `hsl(random-hue 80% 60%)` to transparent — [warp-background.json](https://magicui.design/r/warp-background.json).

### Inferences (static-freeze guidance for a non-animating design tool)
- Freeze frame choice matters: draw Border Beam / Moving Border as a single comet about 15-25% along the top edge; Meteors as 5-8 streaks at mixed positions with 2-3 at reduced opacity; Marquee as a row clipped by both edges with the edge fades; Shine Border with the bright lobe in one corner; Spotlight at its end pose.
- "Gradient ring" (Border Beam, Shine Border, Magic Card, Glowing Effect, Hover Border Gradient, Neon Card, Rainbow Button) is one reusable primitive: a 1-2px stroke with a gradient (linear, radial at a point, or conic wedge), optionally duplicated behind with a large blur at 60-80% opacity for the halo.
- "Fade-masked pattern" (grid 40px #262626 or #171717 on black; dots 16-20px #404040) plus a radial vignette in the page colour (transparent 20% to solid) is the single most reused background recipe across both libraries.
- "Streak" primitive: 1px or 2px line with `transparent, colour, transparent` gradient, doubled with a 4px blurred copy (Sparkles underline, Lamp tube, hero border accents, Compare divider).
- Magic UI's device mockups deliberately use two greys only (no coloured traffic lights); that neutrality is why they sit well in any palette.
- Typical accent sets to offer as presets: Magic UI #ffaa40 to #9c40ff; Magic Card #9E7AFF to #FE8BBB; Aurora Text #FF0080 / #7928CA / #0070F3 / #38bdf8; Aceternity beam #18CCFC / #6344F5 / #AE48FF; lamp cyan-500 on slate-950; background-gradient #00ccb1 / #7b61ff / #ffc414 / #1ca0fb.

## 5. Critique: overuse, "AI slop" tells, restraint, performance, accessibility

### Takeaway
Critics do not single out these libraries by name as "slop"; they target the look the libraries make cheap: dark navy/black with blurred purple-blue glow, glowing or animated gradient borders, gradient headline text, equal-weight bento tiles, and constant decorative motion. Published guidance converges on "one atmospheric effect, one gradient, one animated element per page", product-specific imagery over atmosphere, and real reduced-motion end states. The libraries' own reduced-motion handling is partial.

### Cited Findings
- Jean Galea (13 June 2026) describes the generic AI page as a centred headline, three cards, "and a gradient no one chose"-style output, attributes it to missing context rather than the model, calls Aceternity the animation-heavy option that "appears on many AI-startup landing pages" and Magic UI the calmer companion; advises picking one section library and always reviewing the rendered UI. Short quote: "Your AI coder is designing blind." — [jeangalea.com](https://jeangalea.com/ai-ui-looks-generic/).
- "Gradient Fog" smell: dark navy background with blurred cyan/violet/blue glows applied regardless of product; it signals "modern tech" cheaply and can mask weak composition and typography. Quote: "The blur suggests depth even when the page has none." Deliberate, product-tied gradient use is fine — [AI Smells: Gradient Fog](https://aismells.pages.dev/gradient-fog.html) (no author/date on page).
- "Bento Box Sprawl" smell: bento becomes the default for everything; evenly weighted rounded tiles each with eyebrow, icon and one stat avoid deciding what deserves emphasis; legitimate when content is genuinely modular and scannable — [AI Smells: Bento Box Sprawl](https://aismells.pages.dev/bento-box-sprawl.html).
- Noqta (4 June 2026, bylined "AI Bot", low authority): overused patterns are oversized uniform border radius, random purple-to-blue glowing gradients, excessive letter-spacing on eyebrow labels, fake "Live"/"New" pulsing badges, and a thick coloured border on one side of a rounded card; says Tailwind defaults push output toward purple and Inter — [noqta.tn](https://noqta.tn/en/blog/ai-design-slop-overused-ui-patterns-fix-2026).
- A community "anti AI slop ban list" (GitHub wiki, opinion) bans: default purple-to-blue hero gradient; rainbow gradient headline text (reserve gradient for one element per page); every gradient at 135deg; glow on every card; glow rings under buttons; "everything glows"; glassmorphism on every panel (one glass element per page); animated rainbow or conic-gradient borders (static borders; at most one animated element per page); fade-up on every element; continuously animating elements; decorative floating shapes; three equal cards in a row; centred hero with stacked centred content; two equal-weight hero CTAs; round-number stats; uniform radius everywhere (suggests pills 9999, cards 8-16, inputs 4-6, modals 16-24px). Notably it recommends bento/asymmetric spans as the fix for identical grids — [ux-skill wiki](https://github.com/Laith0003/ux-skill/wiki/Anti-AI-slop-ban-list).
- Search-level findings (not individually fetched): the dark background with soft purple-blue glow is called the most exhausted move on the web and imitators copy Linear's glow but miss its content discipline; bento was listed as overused and predictable in 2025 trend pieces, while a 2026 "reality check" says bento and dark mode keep winning in more conservative form — [webtrends Linear breakdown](https://webtrends.pages.dev/posts/linear-landing-page-breakdown), [digidop 2025 trends](https://www.digidop.com/blog/5-web-design-trends-2025), [studiomeyer 2026 reality check](https://studiomeyer.io/en/blog/webdesign-trends-2026-reality-check), [LogRocket on Linear design](https://blog.logrocket.com/ux-design/linear-design).
- A founder report (search summary only) says replacing the purple gradient with real product screenshots improved conversion — [Indie Hackers post](https://www.indiehackers.com/post/6cb0aa2a02) (not fetched; anecdotal).
- Reduced motion in the libraries: PkgPulse (25 March 2026) marks both Aceternity and Magic UI as not supporting `prefers-reduced-motion`, while admitting the table may describe early versions — [PkgPulse](https://www.pkgpulse.com/guides/react-bits-vs-aceternity-magic-ui-2026). Contradicted in part by current Magic UI source: Retro Grid ships an explicit `@media (prefers-reduced-motion: reduce)` rule, Shine Border uses `motion-safe:animate-shine`, Icon Cloud starts paused when reduced motion is set — [retro-grid.json](https://magicui.design/r/retro-grid.json), [shine-border.json](https://magicui.design/r/shine-border.json), [icon-cloud.json](https://magicui.design/r/icon-cloud.json). Aceternity Tracing Beam hides its animated path with `motion-reduce:hidden` — [tracing-beam.json](https://ui.aceternity.com/registry/tracing-beam.json). Most other components fetched (meteors, marquee, border beam, beams, lamp) show no reduced-motion branch in the extracted source.
- Performance: PkgPulse estimates Framer Motion at about 125KB plus 5-15KB per component and rates bundle risk "Medium-High", with no benchmark or cited source — [PkgPulse](https://www.pkgpulse.com/guides/react-bits-vs-aceternity-magic-ui-2026). Heavier pieces rely on canvas/WebGL or extra libraries: cobe (globe), tsparticles (sparkles), three.js (GitHub globe, canvas reveal) — [Aceternity llms.txt](https://ui.aceternity.com/llms.txt), [globe.json](https://magicui.design/r/globe.json), [canvas-reveal-effect.json](https://ui.aceternity.com/registry/canvas-reveal-effect.json).
- General guidance: a reduced-motion branch should render the end state rather than a shorter animation — [21st.dev on animated component libraries](https://21st.dev/blog/animated-component-libraries) (search summary); animate only transform and opacity, 100-150ms for routine actions and 200-300ms for significant transitions — [ux-skill wiki](https://github.com/Laith0003/ux-skill/wiki/Anti-AI-slop-ban-list).
- PkgPulse also notes Aceternity is dark-first with "limited" light mode that needs rework — [PkgPulse](https://www.pkgpulse.com/guides/react-bits-vs-aceternity-magic-ui-2026).

### Inferences (when an effect serves the content)
- An effect earns its place when it encodes something true about the product or directs attention to one thing: Animated Beam for a real integration/data-flow diagram; Globe or World Map for real geographic reach with real markers; Marquee for more logos or quotes than fit; Border Beam or one halo on the single primary screenshot or the recommended pricing tier; Number Ticker for specific (not round) stats; Terminal for a CLI product; device mockups whenever a real screenshot exists; Progressive Blur and edge fades to resolve genuine overflow; grid/dot patterns at very low contrast as texture behind dense UI.
- It reads as decoration (and as an AI tell) when it is product-agnostic and repeated: meteors, sparkles, vortex, aurora, lamp or beams behind generic copy; rainbow/conic borders on several cards; gradient-clipped text on every heading; a purple-blue glow blob behind the hero; bento tiles of equal weight each with icon plus one line; placeholder gradients where product imagery should be.
- For a static design assistant the practical rules are: at most one atmospheric background per page and none repeated in consecutive sections; at most one gradient-stroke/halo element per viewport; gradient text only on the hero heading (and prefer the neutral silver gradient over rainbow); accent hue chosen from the brand, not the libraries' default orange-violet or cyan-violet; bento only with an explicit dominant tile and real content in tile backgrounds; keep text contrast AA since silver-to-neutral-400 gradients and neutral-500 body on black can fall below 4.5:1 at the dark end (contrast claim is my inference, not measured).
- Because a frozen frame removes the motion that justified many of these effects (meteors, shimmer, marquee), static designs make their decorative nature more obvious; a static tool should bias further toward restraint than the live libraries do.

### Gaps
- No authoritative (named designer or large-publication) critique naming Magic UI or Aceternity directly was found; evidence is blogs, community checklists and anonymous "smell" pages. HN/Reddit/X threads were not retrieved.
- The Impeccable anti-patterns page returned HTTP 410 and could not be cited.
- No measured Lighthouse/Core Web Vitals data for pages built with either library was found.
- No library-published guidance on restraint or on how many effects to combine was found.

## 6. Tech basis, popularity, licensing

### Takeaway
Both are React + Tailwind CSS + Motion (Framer Motion) copy-paste libraries distributed through the shadcn registry (`@magicui/...`, `@aceternity/...`); Magic UI is MIT on GitHub with about 23.3k stars, while Aceternity's free components are governed by its own site licence (free use in end products, no redistribution as a component kit), not a public MIT repo as some comparisons claim.

### Cited Findings
- Magic UI: GitHub magicuidesign/magicui, 23.3k stars, 1.3k forks, MIT, 1,410 commits, tagline "UI Library for Design Engineers", topics framer-motion, nextjs, react, shadcn-ui, tailwindcss, typescript; repo also contains a `skills/magic-ui` folder and AGENTS.md — [GitHub repo](https://github.com/magicuidesign/magicui).
- Magic UI install: `pnpm dlx shadcn@latest add @magicui/globe`; "We have the exact same installation process as shadcn/ui"; an MCP docs page exists — [Magic UI installation](https://magicui.design/docs/installation).
- Magic UI source uses Tailwind v4 syntax (`bg-linear-to-l`, `size-(--icon-size)`, `mask-intersect`, `@container-[size]`) and the `motion` package; keyframes ship as registry cssVars — [border-beam.json](https://magicui.design/r/border-beam.json), [animated-beam.json](https://magicui.design/r/animated-beam.json), [marquee.json](https://magicui.design/r/marquee.json).
- Aceternity: "built with Tailwind CSS and Framer Motion for React and Next.js"; Tailwind v4 compatible; install via `npx shadcn@latest add @aceternity/[component-name]`; `npm i motion clsx tailwind-merge`; some components add cobe, react-syntax-highlighter, react-fast-marquee, react-rough-notation; MCP access listed in the free tier — [Aceternity llms.txt](https://ui.aceternity.com/llms.txt), [Aceternity pricing](https://ui.aceternity.com/pricing), [Grid and Dot Backgrounds docs](https://ui.aceternity.com/components/grid-and-dot-backgrounds).
- Aceternity licence: ongoing, non-exclusive, worldwide licence; unlimited end products for self or clients, modification allowed; prohibited to redistribute items as source/stock, resell on marketplaces, or build themes/templates for sale from them; no attribution requirement stated; the page does not distinguish free from paid items — [Aceternity licence](https://ui.aceternity.com/licence).
- Conflict: PkgPulse states Aceternity is MIT with about 19K GitHub stars and Magic UI has about 18K stars — [PkgPulse](https://www.pkgpulse.com/guides/react-bits-vs-aceternity-magic-ui-2026); contradicted by [Aceternity licence](https://ui.aceternity.com/licence) (custom terms) and [GitHub repo](https://github.com/magicuidesign/magicui) (23.3k). Treat PkgPulse numbers as unreliable.
- Popularity signals: Magic UI Pro "Trusted by 5,000+ developers" — [Magic UI installation](https://magicui.design/docs/installation); Aceternity "Loved by thousands of developers, designers and entrepreneurs" with no count — [Aceternity pricing](https://ui.aceternity.com/pricing).

### Inferences
- Because both distribute through the shadcn registry and expose llms.txt and MCP endpoints, they are explicitly positioned as raw material for AI coding agents, which explains their over-representation in AI-generated landing pages.
- Recreating the static look of these components in a design tool raises no licensing issue for MIT Magic UI; for Aceternity, shipping a bundled "Aceternity kit" of recreated components could conflict with the no-redistribution clause, whereas teaching general recipes (grid + vignette, spotlight ellipse, gradient ring) does not copy source. This is not legal advice.

- Aceternity GitHub star count and whether a public source repo exists were not verified from a primary source.

- Magic UI Pro licence text beyond "commercial use allowed, no resale" was not fetched in full.
